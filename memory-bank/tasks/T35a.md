## Description
Make app navigation addressable through the browser URL so a user can share a link to a page, section, or subsection and have it restored on direct load. Keep each feature in its existing page and interface. In particular, Random Walk modes remain strategies selected through the shared parameter panel and existing physics engine; a URL may select a strategy without creating a separate page, panel, or engine.

## Acceptance Criteria
- [x] Give each top-level app page a stable URL and make desktop and mobile navigation update it consistently.
- [x] Support shareable links to meaningful page sections and subsections using paths, query parameters, and fragments according to the URL plan.
- [x] Resolve URL-owned navigation state before persisted navigation state so stale Zustand state cannot override a shared link.
- [x] Keep Random Walk strategies, including Kac–Goldstein and Masoliver–Lindenbergh, inside the unified Random Walk page, parameter panel, and engine; use URL state only to restore the selected strategy.
- [x] Preserve existing `?data=` run-sharing links; old root links with this parameter still open Random Walk.
- [x] Use the existing Vercel SPA rewrite for nested paths and route unknown paths to the PDE page.
- [x] Verify local direct links, refresh, Back/Forward, and subsection restoration in a browser.
- [ ] Verify direct nested-path loading on the deployed Vercel app.
